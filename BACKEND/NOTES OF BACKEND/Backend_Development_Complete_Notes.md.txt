# Backend Development --- Complete Practical Notes

## A revision + implementation guide for Node.js, Express.js, REST APIs, MongoDB, Mongoose, EJS, Authentication and Deployment

------------------------------------------------------------------------

# 1. What is Backend?

A web application usually has three major parts:

-   **Frontend** → what the user sees and interacts with
-   **Backend** → business logic, authentication, validation, APIs
-   **Database** → stores application data

Typical flow:

``` text
Browser / Frontend
       ↓
HTTP Request
       ↓
Backend Server
       ↓
Route
       ↓
Middleware
       ↓
Controller / Business Logic
       ↓
Database
       ↓
Response
       ↓
Frontend
```

Example:

A user clicks **"Login"**.

``` text
Frontend
   ↓ POST /login
Express Route
   ↓
Validation Middleware
   ↓
Login Controller
   ↓
MongoDB
   ↓
Check email/password
   ↓
Create session/JWT
   ↓
Send response
```

The backend is therefore not just "writing Node.js code". It is
designing a system that receives requests, processes them safely, works
with data, and returns useful responses.

------------------------------------------------------------------------

# 2. HTTP Basics

HTTP is the communication protocol used between client and server.

## Request

A request normally contains:

-   Method
-   URL
-   Headers
-   Body
-   Query parameters
-   Route parameters

Example:

``` http
POST /api/users?role=student
Content-Type: application/json

{
  "name": "Swaliya",
  "email": "example@gmail.com"
}
```

## Response

A response contains:

-   Status code
-   Headers
-   Body

Example:

``` json
{
  "message": "User created successfully"
}
```

------------------------------------------------------------------------

# 3. HTTP Methods

## GET

Used to retrieve data.

``` js
app.get("/users", (req, res) => {
  res.json(users);
});
```

## POST

Used to create data.

``` js
app.post("/users", (req, res) => {
  // create user
});
```

## PUT

Used to replace/update a resource.

``` js
app.put("/users/:id", (req, res) => {
  // update user
});
```

## PATCH

Used for partial updates.

``` js
app.patch("/users/:id", (req, res) => {
  // update selected fields
});
```

## DELETE

Used to delete data.

``` js
app.delete("/users/:id", (req, res) => {
  // delete user
});
```

------------------------------------------------------------------------

# 4. Important HTTP Status Codes

## 2xx --- Success

``` text
200 OK                 → successful request
201 Created            → resource created
204 No Content         → successful, no response body
```

## 4xx --- Client Error

``` text
400 Bad Request        → invalid request
401 Unauthorized       → authentication required/failed
403 Forbidden          → authenticated but not allowed
404 Not Found          → resource doesn't exist
409 Conflict           → conflict, e.g. duplicate email
422 Unprocessable      → validation problem
```

## 5xx --- Server Error

``` text
500 Internal Server Error
502 Bad Gateway
503 Service Unavailable
```

Remember:

**401 = Who are you?**

**403 = I know who you are, but you cannot do this.**

# 9. Express.js

Express is a Node.js web framework that makes it easier to create:

-   Servers

-   APIs
-   Middleware pipelines
-   Web applications

Basic server:

``` js
const express = require("express");

app.listen(3000, () => {
  console.log("Server running");

```

------------------------------------------------------------------------

# 10. Express Middleware

Middleware is a function that runs during the request-response cycle.

``` text
Request
   ↓
Middleware 1
   ↓
Middleware 2
   ↓
Route
   ↓
Response
```

Example:

``` js
app.use(express.json());
```

This allows Express to parse JSON request bodies.

Custom middleware:

``` js
function logger(req, res, next) {
  console.log(req.method, req.url);
  next();
}

app.use(logger);
```

Important:

If middleware does not send a response, it usually needs:

``` js
next();
```

### Application-level


### Router-level


### Built-in

### Third-party

Examples include:

-   cors
-   cookie-parser
-   multer
-   helmet

### Error-handling middleware

``` js
app.use((err, req, res, next) => {
```

# 12. Express Routing

Basic route:

``` js
app.get("/", (req, res) => {
  res.send("Home");
});
```

Dynamic route:

``` js
app.get("/users/:id", (req, res) => {
  console.log(req.params.id);
});
```

Separate router:

``` js
const express = require("express");
const router = express.Router();

router.get("/", getUsers);
router.post("/", createUser);

module.exports = router;
```

Mount it:

``` js
app.use("/api/users", router);
```

Now:

``` text
GET  /api/users
POST /api/users
```

# 13. req.params vs req.query vs req.body

This is one of the most important concepts.

## Route parameters

URL:

``` text
/users/123
```

Code:

``` js
req.params.id
```

## Query parameters

URL:

``` text
/users?city=Pune&page=2
```

Code:

``` js
req.query.city
req.query.page
```

## Body

Request:

``` json
{
  "name": "Swaliya"
}
```

Code:

``` js
req.body.name
```

Easy memory:

``` text
params → identifies resource
query  → filters/searches/options
body   → data being sent
```

# 15. REST API

REST is an architectural style for designing web APIs.

Example resource:

``` text
/users
```

CRUD mapping:

``` text
GET     /users        → get all users
GET     /users/:id    → get one user
POST    /users        → create user
PUT     /users/:id    → replace user
PATCH   /users/:id    → partially update user
DELETE  /users/:id    → delete user
```

Good API naming usually uses nouns:

``` text
/api/users
/api/products
/api/orders
```

Avoid:

``` text
/api/getUsers
/api/createUser
```

# 22. Schema

Schema describes the structure and rules of documents.

``` js
const userSchema = new mongoose.Schema({
  name: {
    type: String,
    required: true
  },

  email: {
    type: String,
    required: true,
    unique: true
  },

  age: {
    type: Number
  }
});
```

------------------------------------------------------------------------

# 23. Model

``` js
const User = mongoose.model("User", userSchema);
```

The model is used to interact with the collection.

Create:

``` js
const user = await User.create({
  name: "Swaliya",
  email: "example@gmail.com"
});
```

Find:

``` js
const users = await User.find();
```

Find one:

``` js
const user = await User.findById(id);
```

Update:

``` js
await User.findByIdAndUpdate(
  id,
  { name: "New Name" },
  { new: true, runValidators: true }
);
```

Delete:

``` js
await User.findByIdAndDelete(id);
```

# 25. Relationships in MongoDB

MongoDB can model relationships using:

## Embedded documents

``` js

  city: String,

```

Useful when related data belongs tightly to one document.

## Referenced documents

``` js
user: {
  type: mongoose.Schema.Types.ObjectId,
```

Then:

``` js
Order.find().populate("user");
```

Use references when entities are large, independent, or shared.

# 27. Async/Await

Database operations are asynchronous.

Use:

``` js
async function getUsers() {
  const users = await User.find();
  return users;
}
```

Error handling:

``` js
try {
  const users = await User.find();
} catch (err) {
  console.error(err);
}
```

Remember:

``` text
async → function can use await
await → waits for Promise result inside async function
```

------------------------------------------------------------------------

# 28. Error Handling

Bad approach:

``` js
try {
  ...
} catch (err) {
  res.send(err);
}
```

Better:

``` js
try {
  const user = await User.findById(req.params.id);

  if (!user) {
    return res.status(404).json({
      message: "User not found"
    });
  }

  res.json(user);
} catch (err) {
  next(err);
}
```

Central handler:

``` js
app.use((err, req, res, next) => {
  console.error(err);

  res.status(500).json({
    message: "Internal server error"
  });
});
```

# 29. Authentication vs Authorization

These are different.

## Authentication

"Who are you?"

Examples:

-   Login
-   Password verification
-   Session
-   JWT

## Authorization

"What are you allowed to do?"

Example:

``` text
Farmer → can edit own farm data
Buyer → can view available products
Admin → can manage users
```

# 30. Password Security

Never store:

``` text
password: "mypassword123"
```

Store a secure password hash.

Common approach:

``` bash
npm install bcrypt
```

Hash:

``` js
const hashedPassword = await bcrypt.hash(password, 10);
```

Compare:

``` js
const valid = await bcrypt.compare(
  password,
  user.password
);
```

Never return password hashes in normal API responses.

------------------------------------------------------------------------

# 31. Sessions and Cookies

A session can store login state on the server.

A cookie can hold a session identifier.

Typical flow:

``` text
Login
 ↓
Server verifies password
 ↓
Server creates session
 ↓
Session ID stored in cookie
 ↓
Browser sends cookie on future requests
 ↓
Server identifies user
```

Important cookie security concepts:

``` text
httpOnly
secure
sameSite
```

------------------------------------------------------------------------

# 32. JWT Authentication

JWT = JSON Web Token.

Typical flow:

``` text
Login
 ↓
Verify credentials
 ↓
Create JWT
 ↓
Send token
 ↓
Client sends token with future requests
 ↓
Middleware verifies token
 ↓
Request continues
```

A common header is:

``` http
Authorization: Bearer <token>
```

JWT is useful, but it does not automatically make an application secure.
Token storage, expiration, revocation strategy, HTTPS, and authorization
still matter.

# 33. Authorization Middleware

Example concept:

``` js
function requireAdmin(req, res, next) {
  if (req.user.role !== "admin") {
    return res.status(403).json({
      message: "Access denied"
    });
  }

  next();
}
```

Then:

``` js
app.delete(
  "/api/users/:id",
  authenticate,
  requireAdmin,
  deleteUser
);
```

A common backend structure is:

``` text
project/
│
├── app.js
├── package.json
├── .env
├── .gitignore
│
├── models/
│   └── User.js
│
├── routes/

├── middleware/
│   └── auth.js
│
├── services/

│
├── views/
│   └── home.ejs
│
```

Responsibilities:

``` text

Controller → handles request/response logic
Service     → business logic
Model       → database interaction/schema
Middleware  → reusable request processing

```

For small projects, you do not need to over-engineer this structure.

# 39. Security Basics

Important backend security concepts:

### Never trust client input

The frontend can be modified/bypassed.

### Hash passwords

Use bcrypt/Argon2 rather than storing plaintext.

### Use HTTPS

Protect data in transit.

### Protect secrets

Use environment variables/secrets management.

### Validate input

Reject malformed/unexpected data.

### Prevent NoSQL injection

Do not blindly pass user-controlled objects into MongoDB queries.

### Prevent XSS

Escape untrusted HTML.

### Protect authentication

Use secure cookies/token practices and expiration.

### CORS

Configure which origins can access your API.

### Rate limiting

Limit repeated requests to sensitive endpoints such as login.

# 42. Pagination

Never return thousands/millions of records at once.

Example:

``` text
GET /products?page=2&limit=10
```

Concept:

``` js
const page = Number(req.query.page) || 1;
const limit = Number(req.query.limit) || 10;

const skip = (page - 1) * limit;

const products = await Product
  .find()
  .skip(skip)
  .limit(limit);
```

For very large datasets, cursor-based pagination can be preferable.

# 50. Debugging Backend Errors

When something fails, don't randomly change code.

Use this process:

### Step 1 --- Read the error

Find:

``` text
Error type
File
Line number
Message
Stack trace
```

### Step 2 --- Identify the layer

Ask:

``` text
Is it frontend?
Route?
Middleware?
Controller?
Database?
Environment?
Network?
```

### Step 3 --- Check inputs

Print/debug:

``` js
console.log(req.body);
console.log(req.params);
console.log(req.query);
```

### Step 4 --- Test independently

Use Postman/curl.

### Step 5 --- Check database

Verify:

-   Connection
-   Collection
-   Document
-   Query
-   Schema

### Step 6 --- Fix the root cause

Do not hide the error with random changes.

# 57. How a Real Request Travels

Suppose:

``` text
POST /api/products
```

with:

``` json
{
  "name": "Apple",
  "price": 150
}
```

Flow:

``` text
Client
 ↓
POST /api/products
 ↓
Express
 ↓
CORS / JSON middleware
 ↓
Authentication middleware
 ↓
Validation middleware
 ↓
Product route
 ↓
Product controller
 ↓
Product service
 ↓
Mongoose model
 ↓
MongoDB
 ↓
Result
 ↓
Controller
 ↓
JSON response
 ↓
Client
```

If you understand this flow, you understand a large part of practical
backend development.

# 58. The Most Important Mental Model

Whenever you build a feature, ask these questions:

### 1. What data do I need?

Example:

``` text
User:
name
email
password
role
```

### 2. Where will I store it?

MongoDB collection:

``` text
users
```

### 3. What API do I need?

``` text
POST /api/users
GET /api/users
GET /api/users/:id
PATCH /api/users/:id
DELETE /api/users/:id
```

### 4. Who can access it?

``` text
Public
Authenticated user
Admin
```

### 5. How will I validate it?

``` text
email
password
required fields
IDs
```

### 6. What happens if it fails?

``` text
400
401
403
404
409
500
```

### 7. How will the frontend consume it?

``` js
fetch("/api/users");
```

This thinking is more valuable than memorizing syntax.

``` text
   ↓

   ↓

   ↓
Security
   ↓

   ↓

   ↓
```

The most important transition is:

``` text
"I know the syntax"
        ↓

        ↓
```

# 62. Final Advice

You are **not supposed to remember every backend concept permanently
after learning it once**.

Real developers constantly look up:

-   Syntax
-   Library documentation
-   Error messages
-   API options
-   Database queries
-   Security recommendations

process**:

``` text
Request
 ↓
Route
 ↓
Middleware
 ↓
Controller
 ↓
Business Logic
 ↓
Database
 ↓
Response
```

If you understand this flow and can independently build CRUD +
authentication + database-backed APIs, you have a strong practical
backend foundation.
